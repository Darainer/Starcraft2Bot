# First recurrent PPO pilot

Verdict: **checkpoint rejected for promotion**. The CPU policy, owned environment,
decision collector, recurrent update and checkpoint reload all ran on real retail
SC2. The trained candidate did not improve resolved outcomes on its target.

The [machine-readable evidence](../experiments/2026-10-31/rl-pilot-v1-evidence.json)
retains exact source, checkpoint, dependency, executable, map, ping, fingerprint,
episode, replay and transition identities, plus optimizer and benchmark values.
Raw logs, observations, weights and replays remain in ignored local storage.
Implementation and commands are in [the pilot guide](../rl-training-pilot.md).

learning path with a small declared budget, rather than establishing useful play.
Repeated fixed-seed starts do not supply independent conditions, and development
uses the same world as training. Longer survival alone does not prove stronger
play. There is no promotion, broader regression matrix or generalization claim.

## CPU measurements

The model has 645,972 parameters and 2,583,888 bytes of float32 weights. Measurements
used an Intel Core i7-12700H, about 32 GB system RAM, PyTorch 2.15.0+cpu and one
Torch CPU thread. Neural timings include semantic tensor encoding, entity pooling,
the GRU and policy/value heads; they exclude game stepping and sampling/decoding.

| Process/context | Entities | Median | p95 | p99 |
| --- | ---: | ---: | ---: | ---: |
| Isolated initial-policy process, one SC2 client observed | 201 | 3.16 ms | 4.30 ms | 6.35 ms |
| Isolated trained-policy process, seven SC2 clients observed | 201 | 12.34 ms | 16.54 ms | 17.46 ms |
| Trainer retaining its episode dataset, eight to seven clients observed | 201 | 16.17 ms | 21.33 ms | 25.77 ms |

The separate trained inference process used about 263 MB resident memory with
three recorded states; the trainer retained about 3.25 GB including its rollout
objects. These are different workloads. Model weight size is not process RAM.
The observed inference cost fits this machine's strategic cadence. This is not
a universal PC requirement or a matched comparison of concurrency throughput.

## Record corrections and separate lifecycle group

The v1 fourth head emitted advisory scouting questions: the retained baseline
scout controller does not consume these requests. The later adapter masks that
policy capability unsupported, while automatic baseline scouting continues.
The 34-logit schema remains available for a future validated question executor.
Also, the v1 `observed_new_completed_unit` label included returning ready contacts,
such as gas workers. The label is now `observed_ready_contact_appeared`; appearance
counts are neither purchases nor causal success labels and never earned reward.
Original frozen artifacts have not been rewritten.

At corrective source `3c38b0e204d0b9d97058c2500ce42c5f12aa2988`, three separate
30-game-second lifecycle checks ended as **time-limit truncations** at loop 672,
with 11 transitions each. Each retained a final-observation bootstrap value and
zero terminal reward; fresh forward passes independently reproduced those values.
The next episode started with zero recurrent memory. The scouting-question head
was inactive with zero log-probability contribution throughout. These checks are
infrastructure validation and do not count toward gameplay acceptance or the
3600-second comparison group.

An additional intentional cancellation at the first director decision joined its
owned worker cleanly, reported `aborted`, and was excluded from learning. No
replay was finalized for that intentionally aborted loop-zero check. Startup and
no-director cancellation paths also have synthetic coverage.
